## Purpose

定義 `User` 建立時，會員代號（member_code）唯一性衝突的自動重試保證，確保在任何 transaction 巢狀情境下（包含被其他已自帶 transaction 的操作呼叫）皆能正確運作。

## ADDED Requirements

### Requirement: 會員代號衝突時自動重試且不受外層 transaction 影響
當系統建立新使用者且自動產生的會員代號（member_code）與既有使用者衝突時，系統 SHALL 自動重新產生代號並重試儲存，直到成功或達重試上限為止。此重試行為 SHALL 在建立操作被巢狀於外層 transaction（例如呼叫端本身已使用 transaction 保護的操作）時，仍正確運作，不因外層 transaction 的狀態受影響而失效。每次代號衝突觸發的重試、以及達重試上限的最終失敗，系統 SHALL 記錄可追蹤的紀錄，以利事後排查根因。

#### Scenario: 首次代號即可用
- **WHEN** 建立新使用者，自動產生的會員代號未與既有使用者衝突
- **THEN** 使用者建立成功，不觸發重試

#### Scenario: 代號衝突後重試成功
- **WHEN** 建立新使用者，自動產生的會員代號與既有使用者衝突，但重試上限內產生了未衝突的代號
- **THEN** 使用者以該未衝突的代號建立成功

#### Scenario: 於巢狀 transaction 情境下代號衝突後重試成功
- **WHEN** 建立新使用者的操作本身被包裹在另一個已開啟的 transaction 中（例如透過 `get_or_create` 呼叫），且自動產生的會員代號首次與既有使用者衝突
- **THEN** 重試機制仍正確運作，最終以未衝突的代號建立成功，不因外層 transaction 先前的失敗狀態而連帶失敗

#### Scenario: 建立操作指定非預設資料庫連線時重試機制仍正確運作
- **WHEN** 建立新使用者的操作明確指定寫入非預設的資料庫連線（例如透過 `save(using=...)` 或資料庫路由），且自動產生的會員代號首次與該連線上的既有使用者衝突
- **THEN** 重試機制在該指定連線上正確運作，不影響其他連線的 transaction 狀態，最終以未衝突的代號在該連線上建立成功

#### Scenario: 重試次數達上限仍衝突
- **WHEN** 建立新使用者，連續多次自動產生的會員代號皆與既有使用者衝突，達到重試上限
- **THEN** 系統拋出明確例外，不靜默失敗、不建立不完整的使用者資料，且記錄可追蹤的錯誤紀錄

#### Scenario: 代號衝突觸發重試時可被追蹤
- **WHEN** 建立新使用者時，自動產生的會員代號與既有使用者衝突，觸發一次重試
- **THEN** 系統記錄該次衝突與重試的紀錄，不靜默重試
